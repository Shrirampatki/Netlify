01
The Model

Large Language Model

A large language model (LLM) is a neural network trained on vast amounts of text to predict the next token in a sequence. That simple objective, at massive scale, produces a system capable of reasoning, writing, summarizing, and following instructions.

The LLM itself is stateless — it has no memory between calls and no ability to act on its own. Everything else in this deck (engines, context, agents, harnesses) exists to make the model useful in a real workflow.

  • 1Trained on massive text/code corpora to predict the next token
  • 2Parameters encode patterns of language, reasoning, and knowledge
  • 3Stateless by default — every call starts fresh unless given context
  • 4Examples: Claude, GPT, Gemini, Llama
02
The Runtime

Engine

The engine is the infrastructure layer that actually runs the model: it serves requests, manages GPU/TPU compute, batches traffic, and streams tokens back to the caller.

Think of the LLM as the "brain" and the engine as the "nervous system and muscles" — the part that turns a trained model into a live, callable service with predictable latency and throughput.

03
The Working Memory

Context

Context is everything the model can "see" at the moment it generates a response — the context window. It includes the system prompt, conversation history, retrieved documents, tool results, and the current question.

Because the model has no memory of its own, context engineering — deciding what to include, exclude, and how to structure it — is often the single biggest lever for output quality.

  • 1System instructions — role, rules, tone
  • 2Conversation history — prior turns in the exchange
  • 3Retrieved knowledge — documents, search results, memory
  • 4Tool/function outputs fed back in as new context
  • 5Fixed window size — older content must be trimmed or summarized
04
The Actor

Agent

An agent wraps an LLM in a loop: the model reasons about a goal, chooses a tool or action, observes the result, and repeats — instead of producing one static answer.

This turns the model from a text generator into something that can search, write files, call APIs, or operate other software on a person's behalf, within defined boundaries.

05
The Discipline

Agentic Engineering

Agentic engineering is the emerging discipline of designing, building, and operating agentic systems reliably — going beyond a clever prompt to production-grade behavior.

It draws on software engineering, MLOps, and prompt/context design, with new concerns unique to agents: evaluation of multi-step behavior, guardrails, and cost/latency at scale.

  • 1Designing tool interfaces and permission boundaries
  • 2Context and memory management across long-running tasks
  • 3Evaluation, tracing, and observability for agent behavior
  • 4Guardrails, human-in-the-loop checkpoints, and error recovery
  • 5Cost, latency, and reliability engineering at scale
06
The Scaffolding

Harness

The harness is the surrounding scaffolding that connects a model to the real world: it manages the agent loop, formats tool schemas, handles retries and errors, and enforces limits like turn count or timeouts.

The same LLM, dropped into different harnesses, behaves very differently — the harness is what makes it a coding assistant, a research agent, or a customer-support bot.

  • AOrchestrates the think → act → observe loop
  • BDefines available tools and their schemas/permissions
  • CManages context assembly, truncation, and memory
  • DEnforces stop conditions, retries, and safety limits
  • EExamples: Claude Code, IDE copilots, custom agent runtimes
07
Putting It Together

How the Pieces Stack

LLM

The trained model — reasoning and language, no memory, no hands.

Engine

Runs the model as a fast, scalable service.

Context

What the model sees at generation time — its working memory.

Agent

An LLM in a loop, choosing actions toward a goal.

Harness

The scaffolding that runs the agent's loop and tools.

Agentic Engineering

The discipline of building all of the above reliably.
